## One model, computed twice

The physical model lives in two places on purpose: `tools/tumbler_calc.py`
computes the build sheet, and `cad/tumbler.scad` computes the same geometry to
cut the parts. They agree to four figures (97.7037 mm shaft spacing, 58.2194
mm ride height). Two implementations in two languages agreeing is stronger
evidence than either alone (**LE-07**). That agreement is not yet gated
(**TB5**).

The chain, from inputs to outputs:

```
barrel ID ──► N_crit = 42.3/√D ──► × 0.45 ──► barrel rpm            (KB)
barrel OD, roller OD, 40° ──► shaft spacing, ride height            (MA1)
barrel rpm × OD/roller ──► roller rpm ──► motor rpm ──► step rate   (KD)
step rate ──► VACTUAL (Pico)  |  OCR1A (Arduino)                    (FA1, FB1)
```

**Three constants must move together** when the real barrel is measured:
`BARREL_OD_MM` in `cad/tumbler.scad`, `firmware/main.py` and
`firmware/arduino/tumbler_uno/tumbler_uno.ino`. Nothing checks that they
agree. That is a candidate gate, and worth writing before the first real
measurement changes one of them.

## Decisions with a technical shape

### FA1 — Why the Pico route uses VACTUAL
The TMC2209 has an internal step generator: write a velocity to register
`0x22` and it spins indefinitely with no step pulses from the controller. For
a machine whose whole job is to hold one speed for six weeks, that removes
every source of timing jitter. Reversal is a sign change. The oscillator is
only good to a few percent, hence calibration (**FD1**).

### FB1 — Why the Arduino route uses Timer1 on D9
See **KI**. Timer1 in CTC mode toggles OC1A in hardware:
`f = F_CPU / (2·N·(1 + OCR1A))`. Quantisation error is bounded by
`1/(2·(OCR1A+1))`, which is 0.056% at the recommended build. One trap is handled in
code: writing `OCR1A` below the current `TCNT1` misses the compare and leaves a
4 ms hole in the pulse train, so `TCNT1` is reset when the target drops.

### FB2 — Why the odometer is a ring in EEPROM
EEPROM endures ~100,000 writes per cell. Saving every 500 revolutions is ~4,800
writes a campaign, which would wear out a fixed cell in about twenty
campaigns. Thirty-two 8-byte slots, each checksummed, and boot takes the newest
valid one: this spreads the wear and survives a power cut mid-write.

### FB3 — Why integer arithmetic and wrap-safe timing
See **KJ** and **LE-09**. Dose is `runSec × rpm_x10 / 600`, peaking near
3.6 × 10⁸, inside a `uint32_t`.

### FC3 — How slip is measured
Expected revolutions come from commanded motion; measured revolutions come
from the hall sensor (**EB1**). Slip is `1 − measured/expected`, reported as a
warning at 15% and latched as a fault at 40%. It needs ten expected
revolutions before it reports anything, so a startup cannot trip it.

### BB3 — How the rubber sheet is held without adhesive
`RUBBER_T` shrinks both liners' outer radius by the sheet thickness, so the
printed sleeve's own springiness clamps the rubber against the barrel wall.
It all comes out for cleaning, which a glued liner never does, and grit
trapped in a glued seam is a permanent contamination source between stages.

## Verification

Every check runs without hardware. `./scripts/check-docs.sh` runs the ones
this Mac can run, and says which it skipped and why.

| Check | What it proves | Kind |
|---|---|---|
| `tools/tumbler_calc.py --selftest` | The mill constant is 42.3; a 4.5-inch barrel lands at 48–62 rpm, as a Lortone 3A does; geometry degenerates correctly | **Against the world** |
| `tools/timer1_calc.py --selftest` | Timer1 arithmetic and its bound; both long-run AVR bugs reproduced numerically | Mixed |
| `firmware/tmc2209.py` | CRC agrees with an independent implementation; the datagram shape matches the datasheet | Against the datasheet |
| `firmware/main.py --selftest` | Control logic, including a simulated campaign landing at ~7 days | Drift guard: the simulation is the system under test |
| `tools/render.sh` | The CAD parses, every part is a manifold solid, nothing collides (with a control) | Against OpenSCAD |
| `firmware/arduino/test` `make` | The sketch compiles for the ATmega328P with no warnings | Against the compiler; needs `avr-gcc` |

*"Against the world"* means the assertion would hold whatever this code
said. *"Drift guard"* means it can only catch the code changing, not the code
being wrong. The distinction is in the Docket framework's §4.
